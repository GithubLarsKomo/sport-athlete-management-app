# Context

VI-001 / GitHub #21 implements first-class Coach access without weakening the existing Authentik trusted-proxy authentication boundary.

# Result

The application now separates authenticated principal from target athlete, persists explicit historical Coach↔Athlete assignments, validates the assignment server-side on every athlete-scoped Coach request, audits actor/target access and exposes an explicit selected-athlete context in the Coach UI.

Coach privilege does not grant Athlete impersonation. Athlete-authored profile/check-in/session/journal writes are denied for Coach. Current Coach mutation is limited to the already-approved plan/adaptation control paths.

Assignment administration remains operator-controlled through the repository CLI; no Admin UI or public role-assignment endpoint was introduced.

# Decisions and assumptions

- Authentik authenticates identity; the app owns `athlete|coach` authorization.
- `x-sam-target-athlete` is an untrusted target selector, never an authorization credential.
- Unknown subjects remain backward-compatible Athlete self-provisioning.
- Coach principals are operator-provisioned and must be provisioned before first Coach login.
- No self-hosted runner is used for this iteration.
