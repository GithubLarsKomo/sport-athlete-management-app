# Context

The first review pass found two implementation-quality gaps after the initial implementation event: Coach mutation needed an explicit capability boundary so Athlete-authored subjective data could not be changed, and Coach UI modules could transiently request athlete-scoped data before initial athlete selection.

# Result

Both were corrected without widening scope.

- Coach write capability is now server-side allowlisted to current plan/adaptation control paths.
- Profile, goals, device import, journal mutation, Morning Check and session completion are denied with `coach_action_forbidden`.
- Denied attempts are audited as `coach.api_denied`.
- Athlete-authored forms and journal controls render read-only for Coach.
- Initial Coach selection no longer produces transient journal/specialist errors.
- Duplicate-merge action is not offered to Coach.
